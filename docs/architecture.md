# Архітектура AI-агента (Rust Build Engineer)

## Проблема
Автоматизація рутинного процесу створення базового кросплатформного Rust-проєкту, налаштування модульного тестування (cargo test) та безперервної інтеграції (CI) без ручного втручання.

## Skills (Навички агента)
1. **project-scaffold** — створює базову структуру Rust-проєкту (`src/main.rs`), `.gitignore` (ігнорує `target/`).
2. **build-and-test** — створює додатковий модуль (`src/math.rs`), додає юніт-тест за допомогою `#[test]`, створює скрипти `ci.sh` та `ci.bat` для запуску `cargo build` та `cargo test`.
3. **github-actions** — генерує файл `.github/workflows/ci.yml` із матрицею для трьох ОС (Ubuntu, Windows, macOS) і налаштовує запуск створених CI-скриптів.

## Commands (Доступні команди)
- `/git-init` — ініціалізує/перевіряє Git та `.gitignore`.
- `/create-project` — викликає `project-scaffold`.
- `/create-build` — викликає `build-and-test`.
- `/create-actions` — викликає `github-actions`.
- `/check` — перевіряє успішність генерації проєкту, компіляції та тестів.
- `/init` — оркестратор, що послідовно запускає всі попередні команди.

## Передача даних та обробка помилок
Дані між етапами передаються через стан файлової системи (наприклад, `/create-build` очікує, що `Cargo.toml` вже створено). Оркестратор (`/init`) перевіряє результат після кожного кроку; якщо будь-яка команда або перевірка (наприклад, тест падає) повертає помилку, процес негайно зупиняється.
