# Журнал взаємодії з AI

**Інструменти:** GitHub Copilot Chat у VS Code (агент Build Engineer) — генерація та перевірка проєкту; Claude — рев'ю роботи на відповідність методичці та доопрацювання інструкцій агента.
**Правило:** у запитах до AI не передавалися токени, паролі чи інші секрети.

## 1. Створення агента (гілка `develop`)
**Суть запиту до Copilot:** створити агента Build Engineer для варіанта 4 (Rust / Cargo / cargo test) за структурою з методички: маніфест `.github/agents/build-engineer.agent.md`, skills `project-scaffold`, `build-and-test`, `github-actions` і команди `git-init`, `create-project`, `create-build`, `create-actions`, `check`, `init`.
**Результат:** створено маніфест, 3 skills, 6 prompt-файлів, `README.md`, `docs/architecture.md`.
**Рішення:** кожен файл переглянуто й порівняно з вимогами методички, після чого закомічено в `develop`.

## 2. Перший запуск оркестратора (гілка `feature/hello-world`)
**Запит:** `/init`

**Помилка 1 — замість оркестратора створювався `.github/copilot-instructions.md`.**
Copilot не виконував кроки агента, а генерував файл-конспект з описом проєкту.
*Причина (встановлено пізніше, див. п. 6):* `/init` — вбудована команда Copilot, яка має пріоритет над однойменним prompt-файлом.
*Тимчасове рішення:* запуск через явне прикріплення файлу `#init.prompt.md`.

**Помилка 2 — зупинка через відсутність cargo.**
На кроці `create-project` перевірка `cargo check` завершилась помилкою «Ім'я cargo не розпізнано». Оркестратор за правилами зупинив `/init` і не перейшов до наступних кроків.
*Рішення:* встановлено Rust через rustup, перезапущено VS Code (оновлено PATH). Повторний запуск пройшов успішно.

## 3. Перевірка реакції на зламаний тест
**Запит:** `#check.prompt.md` після зміни очікуваного значення тесту на `assert_eq!(add(2, 1), 4)`.
**Відповідь агента:** звіт PASS/FAIL; `cargo test` — FAIL (очікується 4, фактично 3); «Проєкт не змінювався».
**Висновок:** команда `check` працює в режимі лише читання і не приховує помилку.
**Рішення:** тест повернуто до правильного значення `2, 2`.

## 4. Рев'ю роботи (Claude)
**Запит:** «Перевір чи добре я виконав лабораторну» (звіт + методичка).
**Виявлені невідповідності:**
- workflow не зберігав виконувані файли — розділ Artifacts порожній, хоча у звіті заявлено протилежне;
- тригери `push` / `pull_request` не обмежені гілками `develop` / `master`;
- виконуваний файл називався `hello_world`, тест — `adds_two_numbers` (у методичці — `hello` і `BasicAddition`);
- попередження компілятора `dead_code` для функції `add`;
- у skills не було «Прикладу входу» і «Типового сценарію помилки», у commands — «Команд перевірки»;
- відсутні `docs/usage.md` і журнал AI;
- у робочій копії залишився незакомічений зламаний тест (`2 + 2 == 5`) після демонстрації `check`.

**Рішення:** погоджено доопрацювання; кожну зміну переглянуто перед комітом.

## 5. Доопрацювання агента та проєкту
**Зміни:**
- `ci.yml`: тригери для `develop`, `master`, `main`, `feature/**`; `shell: cmd` для `ci.bat`; крок `actions/upload-artifact@v4` (артефакти `hello-<os>`);
- `Cargo.toml`: `[[bin]] name = "hello"`; тест перейменовано на `basic_addition`, повернуто `assert_eq!(add(2, 2), 4)`;
- `main.rs` викликає `math::add` — попередження `dead_code` прибрано;
- `ci.sh` / `ci.bat`: після `cargo build` і `cargo test` запускають `hello` і виводять `CI: PASS`;
- skills: frontmatter (`name`, `description`), «Приклад входу», «Типовий сценарій помилки»;
- prompts: «Команди перевірки», «Повідомлення про помилку», поле `agent: Build Engineer`; `check` розширено до 10 перевірок;
- маніфест: заборона створювати неописані файли (зокрема `copilot-instructions.md`), комітити та пушити без запиту;
- додано `docs/usage.md` і цей журнал.

**Перевірка:** `.\ci.bat` → `1 passed; 0 failed`, `Hello, world!`, `CI: PASS`.

## 6. Конфлікт з вбудованою командою `/init`
**Запит:** повторний `/init`.
**Помилка 3:** Copilot знову створив `.github/copilot-instructions.md` (15 кроків, +48 рядків) у режимі Agent замість Build Engineer.
**Причина:** назва `/init` збігається з вбудованою командою Copilot, яка генерує файл інструкцій для робочого простору.
**Рішення:** зміни відхилено (Undo); у `init.prompt.md` додано `name: init-project`. Файл лишився `init.prompt.md`, як у методичці, а команда викликається як `/init-project`. Відхилення описано в `docs/architecture.md`.

## 7. Агент не розпізнавався
**Помилка 4:** у `init.prompt.md` попередження «Unknown agent 'Build Engineer'. Available agents: agent, ask, edit, Ask, Plan».
**Причина:** у VS Code була відкрита батьківська тека `lab1`, а Copilot шукає `.github/agents`, `.github/prompts`, `.github/skills` у корені робочого простору.
**Рішення:** відкрито теку `409CSAD4` (File → Open Folder). Агент Build Engineer з'явився у списку режимів чату, попередження зникло.

## 8. Повторний запуск оркестратора (ідемпотентність)
**Запит:** `/init-project` у режимі Build Engineer.
**Відповідь агента (19 кроків, 45 с):** «проєкт уже відповідав вимогам, тому файли не змінювалися»; `cargo check`, `cargo run`, `cargo build` — успішно; `cargo test` — `1 passed; 0 failed`; `ci.bat` — `CI: PASS`; створено `target\debug\hello.exe`; `target/` не відстежується Git; workflow коректний.
**Зауваження:** `ci.sh` і YAML-парсер локально не запускались (на Windows немає `bash` і Python-модуля `yaml`). `ci.sh` перевіряється в GitHub Actions на Linux і macOS.
**Висновок:** повторний запуск не руйнує проєкт і не дублює конфігурацію.

## 9. Конфлікт у pull request
**Помилка 5:** PR `lab1/finish` (feature/hello-world → develop): «This branch has conflicts» у файлах `init.prompt.md`, `README.md`, `docs/architecture.md`, `docs/usage.md`. Перевірки CI — 3 успішні.
**Причина:** ті самі файли змінювались окремими комітами в обох гілках (у `develop` — версія без `name: init-project`).
**Рішення:** актуальні файли агента й документації скопійовано з feature в `develop` (`git checkout feature/hello-world -- ...`), після чого `develop` злито у feature. PR не зливається до перевірки викладачем.
